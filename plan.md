1. Objective

Build a Quiz Management System where:

Admin users can create quizzes with multiple question types (MCQ, True/False, Text).

Public users can take quizzes without authentication.

A results page displays score and detailed feedback.

The goal is to deliver a production-ready, stable core workflow within a 2-hour coding session.

2. Assumptions

Only Admin users (via ActiveAdmin) can manage quizzes.

Public users do not require login.

Supported question types:

mcq

boolean

text

MCQ options stored as JSON.

Text questions use simple exact-match scoring.

Submissions are shown immediately (not saved).

Interface uses vanilla HTML/CSS/ERB for speed and reliability.

3. Scope Chosen for 2-hour Limit
✔ Included

Quiz & Question models

ActiveAdmin admin panel with nested question forms

Public landing page listing all quizzes

Public quiz-taking UI

Scoring logic

Results page with correctness breakdown

Basic styling enhancements for good UX

Deployment to Render

✖ Excluded

Authentication for public users

Saving quiz attempts

Timer, pagination, or question randomization

Fuzzy text matching

Analytics + dashboards

Advanced styling frameworks

These were intentionally deprioritized to deliver the core workflow reliably.

6. Admin Panel (ActiveAdmin)

Create/Edit Quizzes

Nested Questions form

JSON text input for MCQ options

Position field used for ordering

Ransack filters disabled/limited to avoid search errors

Nested form enables fast quiz creation without navigating separate pages.

7. Public Interface
Landing Page (/)

Displays list of available quizzes

Clean card-style UI

Quiz Page (/quizzes/:id)

Renders questions with styled UI elements

MCQ: radio buttons

Boolean: True/False buttons

Text: input field

form_with uses local: true + data: { turbo: false } to bypass TurboStream issues

Submit Flow

POST /quizzes/:id/submit

Evaluates user answers

Computes score

Stores score + results temporarily in session

Redirects to GET /quizzes/:id/result

Results Page

Shows score

Card-style results with:

User answer

Correct answer (if wrong)

Visual indicators (✓ / ✗)

8. Trade-offs and Decisions
✔ Focusing on core functionality

Instead of advanced UX or persistent submissions.

✔ Using ERB instead of React

Much faster to build under time constraint.

✔ ActiveAdmin for admin panel

Instant CRUD with minimal boilerplate.

✔ Avoiding TurboStream

Explicitly disabled to ensure predictable form behavior.

✔ No submission storage

Time-saving; easily extendable later.
